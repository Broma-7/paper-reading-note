# 从精读笔记到用户阅读笔记：改写对照

依据 AdaRSI、MobiAgent 的精读笔记、用户示例及 EmbodiedEvo 阅读笔记的修改反馈提炼。具体事实仅供理解转写方式；新任务读取目标论文材料。

## 从术语到具体问题

精读材料：

> 长任务失败可能来自 harness，也可能来自 executor；先优化调用流程，再对仍不可靠的子步骤归因与训练。

用户的写法：

> **动机：机器人任务失败后，什么时候该改调用流程，什么时候才值得训练模型？**
>
> 假设任务是：“打开微波炉，把碗放进去，然后启动。”
>
> 机器人抓不到门把手，可能是底盘停得太远、指令不合适，也可能是它在当前条件下确实不会稳定地完成开门动作。

先让读者看见失败，再引出区分；术语跟在具体意义之后。随后可用‘管什么／可以改什么’表区分 Harness 与 Executor。

## 从条目到沿图讲解

精读材料：

> Planner 输入全局目标、当前观测、历史、技能目录，输出子指令和技能标签。来源为 GPT-5.4。历史包括评估结果与失败证据。

用户的写法：

> **左上 Planner：决定现在该做哪一件事**
>
> 它读取四类信息：**全局目标、当前画面、执行历史、可用技能目录**，输出两样东西：
>
> 子任务指令：“抓起第二个罐子。” 技能类型：“抓取。”
>
> 文字指令告诉执行器对哪个东西做什么，技能类型告诉路由器启用哪个动作专家。

再用罐子掉落说明为何下一步需要重规划。模型来源可移到模块表，不挤在每段开头。‘左上’须以实际图片核对。

## 图片编号要在正文中可见

图片下方单独写论文原图号和简短图题，再开始读图说明。只选论文中的部分图时保留原编号，例如图 5 后可以接图 12。保存的 Markdown 用相对图片路径，聊天中展示用绝对路径。

```markdown
![探索与测试流程](figures/fig-05.png)

**图 5｜整体流程：探索 → 保存 Skills/Lessons → 冻结 → 新场景执行。**

从左向右看，Playground 中的 agent 根据执行反馈修改代码……
```

alt 是图片描述，不能代替预览中可见的图题。正文引用“图 5”时，读者应能直接找到相同编号。

## 删除防误读式限定，直接讲机制

“防误读式限定”是在主解释之外，反复补充“不代表什么、不能推断什么、并非什么”。改写时删掉这类旁支；必要信息用准确的正面表述承载。

| 原写法 | 改写 |
|---|---|
| 限制平移目标变化，不保证实际精确移动 8 mm，也不是通用最优参数 | 每次发出的平移目标变化限制在 8 mm 以内 |
| 改代码或报错不会撤销已经发生的物理动作 | 下一段程序接着当前机器人状态继续执行 |
| 原生动作是 25 Hz，这不表示模型每秒推理 25 次 | 若频率与机制无关，整句省略；需要时只写“原生动作按 25 Hz 执行” |
| 后续成功不能证明 8 mm 参数单独造成成功 | 直接描述复用过程：“Test 搬运时调用了限步控制方法，随后完成堆叠” |
| 图中的机器人只是示意，实验实际在仿真中进行 | 删除这句图后补充，在结果句中写“在 RoboDojo-Sim 评测中……” |

事实核查仍需准确，成稿通过合适的主语、阶段、单位和场景限定主张。方法依赖的前提放进机制解释，例如“基础策略偶尔能完成开门时，可以反复采集成功示范”。

## 将更新方式并排比较

架构、训练和问答里分散的内容，可组织为：

| 模块 | 来源／初始化 | 本文训练时更新吗 | 作用 |
|---|---|---|---|
| Planner | 外部模型调用 | 未报告微调该模型 | 选择下一子任务与技能 |
| 共享 VLM | 预训练主干 | 按具体平台注明 | 处理图像与语言 |
| 动作专家 | 预训练动作模型初始化 | 更新 | 生成技能动作 |

目的是回答‘谁在学、谁只是被调用’，不为罗列所有参数。不能为缩短表格抹平平台差异。

## 让数据采集变成可想象的过程

精读材料：

> 从问题状态反复运行基础策略，筛选成功轨迹；也可用仿真真值驱动脚本专家生成示范。

用户的写法：

> **第一种：反复尝试，留下成功片段。** 如果基础 VLA 偶尔能开门，就让它从问题状态反复尝试，把成功的操作记录下来。
>
> 例如，假设尝试 20 次，成功 3 次，就保留这 3 段作为示范。

再讲脚本专家，将特权信息的用途写进机制：脚本利用仿真真值生成示范，部署策略根据自身观测执行。

## 删减与保留

| 精读内容 | 阅读笔记的处理 |
|---|---|
| 导读地图、下一站、待讲、进度 | 删除，不把未讲解说成论文没有该内容 |
| 问答中的概念澄清 | 融入正文，通常删除 Q/A 标签 |
| 每个代码行号、尺寸、归一化步骤 | 按主机制需要选用，不默认全搬 |
| 下载、环境兼容、核验过程 | 删除，只保留影响结论的实际差异 |
| 真实任务案例 | 优先贯穿全文，保留实验背景 |
| 教学数字 | 留必要的，标为假设或示意 |
| 模块共享、训练范围、特权信息 | 放在对应机制附近 |
| 防误读式限定 | 删除旁支；必要机制改成正面表述，事实范围融入主句 |
| 论文图片 | 图片下方另写可见的原图号和简短图题，正文引用与之对应 |
| 实验和局限 | 默认只保留与主方法解释直接相关的少量结果，平台和设置融入结果句；要求实验分析时再展开 |

## 可迁移的范围

示例来自机器人系统论文。复用的是‘具体问题 → 主办法 → 对图拆解 → 例子连接 → 必要训练／数据解释’，具体模块随目标论文组织。用户当前指令可以改变篇幅、侧重点与格式。
