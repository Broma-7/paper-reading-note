### **AdaRSI: On-Demand Recursive Self-Improvement for Embodied Agents**

2026.10.14 东北大学、智元机器人（AgiBot）、中国科学院大学

**动机：机器人任务失败后，什么时候该改调用流程，什么时候才值得训练模型？**

假设任务是：“打开微波炉，把碗放进去，然后启动。”

机器人抓不到门把手，可能是底盘停得太远、指令不合适，也可能是它在当前条件下确实不会稳定地完成开门动作。

这对应论文区分的两个层次：

| 层次                          | 管什么           | 可以改什么                           |
| ----------------------------- | ---------------- | ------------------------------------ |
| Harness：工具、技能和调用流程 | 怎么使用已有能力 | 站位、操作顺序、指令、重试和检查方式 |
| Executor：执行动作的 VLA 策略 | 实际动作怎么做   | 通过微调更新模型权重                 |

具体顺序是：

1. 冻结基础 VLA，先调整工具、指令和任务流程。
2. 对仍失败的子步骤，恢复同一个仿真状态，换指令、换接近方式重试。
3. 如果这些调整仍不能让它可靠完成，就收集该子步骤的示范，训练一个专用策略。
4. 比较新旧策略，再决定在哪一步调用新策略。

[原示例配图位置：AdaRSI 图 3：方法流程]

**左上蓝框**改工具和流程，**中上灰框**判断失败原因，**左下橙框**训练选中的子步骤策略，**右侧**是改进完成后的部署系统

**1．Agent：决定下一步做什么，也负责修改系统**

论文使用的 coding agent 标为 GPT-6.1-sol，通过 Codex 运行。它负责理解任务、编写工具和流程、查看执行反馈，以及决定要不要训练某个子步骤。

沿用微波炉例子，它做的决策类似：

> 先导航到微波炉；调整站位；调用开门策略；看门是否打开；成功后再拿碗。

具体抓把手、拉门的连续动作，由下面的 VLA 策略执行。

**2．Harness：把这些决策变成可重复使用的工具和流程**

看左上框里的三项：`tools · skills · procedure`。

| 组件      | 含义                        | 示例                                   |
| --------- | --------------------------- | -------------------------------------- |
| Tools     | 可以被 Agent 调用的具体工具 | navigate()、reset_arm()、observe()     |
| Skills    | 可复用的操作技能或调用逻辑  | 移动到微波炉前、调整抓取前位姿         |
| Procedure | 完整任务的执行流程          | 先导航、再开门、然后放碗、最后检查成功 |

它为什么重要？因为动作策略需要合适的起始条件。即使已经训练出开门策略，底盘停在错误位置，它也可能失败。Harness 既组织任务，也把机器人送到策略实际要工作的状态。论文允许导航、复位等工具直接控制机器人，但规定具体物体操作子步骤由策略库里的策略执行。

**3．基础 VLA：提供原本就有的动作能力**

图中带雪花的 **Base VLA** 是 **GR00T N1.5**，记作 $\pi_0$。

雪花表示：**在前面的 harness 改进阶段，基础 VLA 权重冻结。** 系统先尝试更好的站位、指令和执行顺序，利用它已经具备的能力。

**4．策略库：保存基础策略和后来补练的策略**

看右侧 **Policy Library**：

- **Default $\pi_0$**：基础策略，默认使用。
- **Recommended for sub-step k**：为某个子步骤推荐的微调策略。
- **Other trained policies**：其他已经训练并保留下来的策略。

所以，“补练开门”后的部署过程可以是：

```Plain
导航、调整站位       → harness 工具
打开微波炉门        → 专门微调的开门策略
拿碗、放碗、按启动  → 基础 VLA
```

| 模块       | 来源 / 初始化             | 本方法中怎样更新               | 作用                   |
| ---------- | ------------------------- | ------------------------------ | ---------------------- |
| Agent      | GPT-6.1-sol               | 未报告权重更新                 | 写流程、诊断、选择调用 |
| Harness    | 最小工具集，经 agent 改写 | 修改工具、技能和流程           | 组织步骤、站位与检查   |
| 基础 VLA   | GR00T N1.5                | 保留基础版本；harness 阶段冻结 | 执行已有操作           |
| 子步骤策略 | 基础或已有策略            | 针对选定子步骤微调             | 补足局部动作能力       |

**如何采集成功示范数据**

论文给了两种办法。

**第一种：反复尝试，留下成功片段。** 如果基础 VLA 偶尔能开门，就让它从问题状态反复尝试，把成功的操作记录下来。

例如，假设尝试 **20 次，成功 3 次**，就保留这 3 段作为示范。这里的数字是示意。它的前提是：原策略至少有机会成功。

**第二种：agent 写一个脚本专家来做。** 如果基础 VLA 很难采到成功，agent 可以编写脚本，利用仿真提供的**物体真实位置、门的关节状态等信息**，生成操作示范。

也就是说，系统可以先用信息更充分的脚本做出成功动作，再让 VLA 学习。论文明确说明：这些特权信息用于生成和标注训练数据，部署时不给机器人。

### **MobiAgent: Dual-Loop Recursive Policy Self- Improvement for Long-Horizon Mobile Manipulation**

2026.10.2 香港大学、Astribot、南方科技大学

**动机：把长任务拆成可复用的技能，执行时靠视觉反馈纠错，再把执行经验整理成数据，继续训练技能策略。**

[原示例配图位置：MobiAgent 图 1：任务与内外循环总览]

作者主要针对三个问题：

1. **长任务会把小错误累积起来。** 一次抓取成功，不代表整项任务能完成。用一个**示意数字**理解：假设有10个必要环节，每个独立环节的成功率都是90%，整串全成功的概率只有约 **34.9%**。所以系统需要在中间检查结果，并有机会补救。论文将这种错误累积列为核心挑战。
2. **技能怎样拆分，会影响复用和纠错。** 作者希望用“靠近”“抓取”“放入”等原子技能组织任务。例如，抓第一个、第二个、第三个罐子，可以复用同一个抓取专家，只改变目标指令；投放失败后，也能重新组合“靠近 → 抓取 → 放入”。同时，不同行为使用各自的动作专家，以减少移动和手臂控制共同训练时的相互干扰。
3. **部署经验需要进入下一轮训练。** 机器人执行过很多次任务，会留下视频、状态和动作记录。作者希望自动完成切片、描述、核验和技能归类，把其中合格的片段变成训练数据，减少人工整理工作

于是，MobiAgent 把这件事分成两个时间尺度：

| 循环               | 什么时候工作             | 负责什么                                         |
| ------------------ | ------------------------ | ------------------------------------------------ |
| Inner Loop，内循环 | 正在执行任务时           | 规划下一步、调用技能、看结果，决定继续或重新规划 |
| Outer Loop，外循环 | 一轮任务结束后，离线进行 | 整理执行轨迹，用筛选后的技能片段继续训练         |

[原示例配图位置：MobiAgent 图 2：双循环框架]

1. **左上 Planner：决定现在该做哪一件事**

它读取四类信息：**全局目标、当前画面、执行历史、可用技能目录**，输出两样东西：

> 子任务指令：“抓起第二个罐子。” 技能类型：“抓取。”

文字指令告诉执行器**对哪个东西做什么**，技能类型告诉路由器**启用哪个动作专家**。前一步完成或失败后，再根据新画面生成下一项子任务。图中左侧的 **Next Subtask** 就是当前要执行的那一步。

为什么要有这一层？还是看三个罐子的例子：第二个罐子掉到了桶外，此时下一步应该是重新靠近它。Planner 用当前场景和失败历史决定这个变化。

2. **中上 Executor：共享视觉语言理解，动作按技能分工**

看中间绿色框：上面一条灰色的 **Shared VLA / Pretrained VLM**，下面连着多个 **Action Expert**。

这里有两个层次：

- **共享 VLM**：来自 π0.5 的 **PaliGemma**，处理图像、指令等上下文。它的语言主干是 `gemma_2b`，视觉编码器是 SigLIP。
- **技能动作专家**：每个约 **300M参数**，用 flow matching 生成连续动作块。Planner 给出技能类型后，系统选择对应专家参与这次动作生成。

例如，“抓起第一个罐子”和“抓起第二个罐子”可以复用抓取专家；目标物体通过指令和图像区分。切换到移动技能时，则使用移动对应的专家。共享主干让技能复用感知与语言处理，独立专家让不同动作行为保留各自的参数。

**图中4个专家只是示意。** BEHAVIOR 实验用了6个，S1真机用了5个；公开 RoboCasa 实现也有6个，但技能分类不同，例如抓取、放置共同归入 `pnp` 专家。

3. **右上 Critic：根据画面判断这一步做成了没有**

它读取当前子任务，以及**三个时间点的观测窗口**，输出状态和后续建议：

| 视觉判断             | 后续处理                 |
| -------------------- | ------------------------ |
| complete：完成       | 返回 Planner，安排下一项 |
| incomplete：尚未完成 | 继续当前技能，或重新规划 |
| error：失败          | 返回 Planner，重新规划   |

4. **下半部：把执行记录送回同一套技能策略**

沿下半部从左往右看：

**Data Curator** 把长轨迹切成技能片段、配文字说明并核验 → **Skill Generator** 把片段归到技能类别 → **Skill Trainer** 用整理后的数据更新策略。右侧向上的箭头，就是把更新后的策略用于下一轮部署。启动时会建立技能目录，后续部署数据主要映射到已有目录并继续微调。

| 模块       | 来源／初始化            | 参数规模                     | 本文训练时更新吗                  | 作用                     |
| ---------- | ----------------------- | ---------------------------- | --------------------------------- | ------------------------ |
| Planner    | GPT-5.4 调用            | 未公开                       | 未报告微调该模型                  | 选择下一子任务和技能     |
| 共享 VLM   | π0.5 的 PaliGemma       | 语言部分约2B，另有视觉编码器 | RoboCasa 全部更新；S1冻结视觉部分 | 处理多模态上下文         |
| 动作专家   | π0.5 动作专家初始化     | 每个约300M                   | 更新                              | 生成技能对应动作         |
| Critic     | GPT-5.4 调用            | 未公开                       | 未报告微调该模型                  | 视觉核验与反馈           |
| 外循环代理 | Gemini-3.1-Pro／GPT-5.4 | 未公开                       | 未报告微调这些模型                | 整理数据、归类、组织训练 |
